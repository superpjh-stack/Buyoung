# 부영기업 제조AI MES — 시스템 명세

## 1. 시스템 아키텍처 개요

```
[Physical Layer]          [Edge Layer]           [Data Layer]           [App Layer]
설비·센서               Edge Collector          RDBMS + Vector DB      Web / POP / Mobile
────────────────         ────────────────         ────────────────         ────────────────
PLC (포밍·용접)    →    OPC-UA / Modbus  →    정형: PostgreSQL       관리자 Web Dashboard
IoT 센서           →    MQTT / Kafka     →    비정형: pgvector        현장 POP (터치PC)
비전카메라         →    Edge Buffer      →    시계열: 공정DB          스마트패드 (입고/출하)
스마트패드         →    API Gateway      →    이미지: CAD/비드        현황판 (대시보드)
                                                                        모바일 알림

                                              [AI Agent Layer]
                                              CAD 견적AI + RAG Agent + ML Engine
```

## 2. AI 서브시스템 상세

### 2.1 CAD 견적 자동화 AI (핵심 공정: 수주·견적)

**목적**: CAD 도면(DWG/PDF) 입력 → 자동 견적 산출 → ERP/MES 연계

**파이프라인**:
```
① CAD 도면 입력 (DWG/PDF)
② CAD Parsing (Autodesk API) + Vision AI (YOLOv8 + OCR) 병렬 실행
③ 객체 데이터 정합성 검증 (Confidence Score 산출)
④ Feature Engineering (홀 수량, 절단 길이, 두께, 재질, 형상 복잡도, 용접 길이 등)
⑤ GNN 기반 BOM 자동 생성 (Rule → GNN 관계 추론)
⑥ XGBoost 기반 공정별 원가·견적 산출
⑦ SHAP 기반 원가 영향 변수 설명 (Explainable AI)
⑧ 결과 데이터 저장 → 재학습 루프
```

**입력 데이터**:
- 정형: CAD 객체 정보(홀·슬롯·길이·형상), 치수, 재질, 두께, 원자재 단가, 견적 이력
- 비정형: CAD 도면(DWG/PDF), 작업표준서, 견적 기준서

**출력**: 자동 견적서, BOM, 공정별 원가, 납기 예측 정보

**AI 성능 목표**:
| 항목 | 목표 |
|------|------|
| CAD 객체 인식 정확도 | 80% 이상 (IoU 0.5 기준 F1) |
| 견적 산출 정확도 | ±5% 이내 (MAPE 기준) |
| BOM 생성 정확도 | 85% 이상 (Precision/Recall/F1) |
| 납기 예측 정확도 | 85% 이상 |
| 설명가능성 신뢰도 (SHAP) | 90% 이내 (전문가 평가 일치율) |

### 2.2 RAG 기반 AI Agent (입고/보관 + 보관/출하 공정)

**기반 기술**: LLM + Vector DB (pgvector) + LangChain / LangGraph

**Vector DB 구성 (비정형 지식베이스)**:
- CAD 도면 및 설계 데이터
- 작업표준서(SOP) 및 공정 조건 기준
- 품질 기준서 및 검사 매뉴얼
- 설비 운영·유지보수 문서
- 견적 이력 및 BOM 데이터
- 고객 요구사항 및 클레임 데이터

**입고 AI Agent 기능**:
- 입고 스캔 → LOT 조회 → 기준 비교 → 이상 여부 판단 → 생산 연계
- 자재 이력 조회, 공급처 품질 패턴 분석, 이상 입고 대응

**출하 AI Agent 기능**:
- 출하 요청 → LOT 조회 → 품질 검증 → 승인 판단 → 대응 가이드
- 납기 리스크 분석, 클레임 원인 분석

**질의 시나리오 예시**:
```
- "이 도면 견적 왜 이렇게 나왔어? 주요 원가 요소는 뭐야?"
- "지금 생산 중인 공정 상태 정상인가?"
- "최근 불량이 증가한 공정과 원인은 뭐야?"
- "특정 LOT의 생산 이력과 검사 결과 보여줘"
- "납기 지연 위험 있는 오더 있어?"
```

### 5.2 데이터 계층 구조

```
정형 데이터 (PostgreSQL / RDBMS)
  - 작업지시·공정 진행 (Job/LOT 기반)
  - 원자재 입고·LOT
  - 공정 데이터 (압력, 속도, 전류, 온도, 길이, 각도)
  - 품질 검사·불량 데이터 (유형, 위치, 발생 시점)
  - 설비 상태·센서 데이터 (진동, 전류, 온도)

비정형 데이터 (pgvector / Vector DB)
  - CAD 도면 및 설계 데이터 (DWG/PDF)
  - 작업표준서(SOP), 공정 조건 기준
  - 품질 기준·검사 매뉴얼
  - 설비 운영·유지보수 문서
  - 견적 이력·BOM, 클레임 데이터
```

### 5.3 데이터 흐름 (Digital Thread)

```
수주·견적 (CAD AI)
    ↓ BOM + 공정라우팅
입고/보관 (AI Agent)
    ↓ 자재 LOT
포밍·용접 (IoT 수집)
    ↓ 생산 LOT + 품질 데이터
포장·출하 (AI Agent)
    ↓ 출하 이력 + 클레임
ERP 연계 ←→ MES ←→ 데이터관리시스템
```

## 9. AI 모델 검증 계획

- **검증 기간**: PoC 완료 후 실제 생산라인 기준 3개월 이상 데이터 확보
- **검증 방식**:
  - 도면 기반 견적 결과 vs 실제 생산 원가 비교 (MAE, MAPE, R²)
  - AI 적용 전/후 견적 시간 및 정확도 비교
  - SHAP 변수 중요도 Top-N vs 전문가 평가 일치율
- **Human-in-the-loop**: 시범운영 중 관리자가 AI 추천값 검토·수정·승인 후 운영계획 반영
